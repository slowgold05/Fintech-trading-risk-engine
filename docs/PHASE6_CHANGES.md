# Phase 6 changes — 2026-11-04

This note records the simulator, auditor export, and artifact pack for Phase 6. The roadmap gate is a two-minute video, a polished README, and the full pack. The video was not recorded. The pack is in the repository as drafts. Nothing here was deployed, and nothing was marked approved.

## Why these changes exist

Phase 6 asks for an attack simulator mapped to MITRE ATT&CK, an LLM that drafts SAR narratives from the case's event ids with a verifier, an auditor view and evidence export, and GRC Sentinel monitoring this repo. The GRC output is a tabletop report, testing workpapers for five key controls, and the artifact pack.

The roadmap's own cut list puts an external SAR model first, then network attack tooling, then passkeys, then crypto and replay. This build keeps the GRC substance and records those cuts. It does not call an external model, does not scan the public demo, does not add passkeys, and does not add crypto or replay mode.

## Tabletop

`python -m app.scripts.run_tabletop` builds a private sqlite database, runs an in-process client, and writes `grc/tabletop/2026-11-04-exercise.md`. It does not read `DATABASE_URL` and it does not call the public API. On 2026-11-04 every scenario was caught:

| Scenario | MITRE | Result |
| --- | --- | --- |
| Reused refresh token | T1550.004 | The old cookie is rejected after rotation. |
| Another account's cash movements | T1078 | ATT&CK has no IDOR technique. The second account cannot list the first account's movements. |
| Credential stuffing | T1110.004 | Five failures across three emails from one address deny the login. |
| Sell without holdings | No ATT&CK technique | The order book returns `Not enough holdings to sell`. |

| Structuring | No ATT&CK technique | SM-AML-01 fired on labeled scenario `three-deposits-under-the-threshold`. No payment was sent. |

The exercise did not open an incident and did not start a customer-notice clock. It is pending exercise owner review.

## SAR drafts

`POST /compliance/sar-drafts` stores a template. The template names the case, repeats the case summary, lists that case's event ids, and says filing is outside the draft. The verifier rejects a cited set that is not exactly those ids, an extra event token, and the phrases `file a sar`, `do not file`, `we recommend filing`, `sar is required`, and `filing decision`. A failed verification is not stored. An auditor cannot create a draft. A reviewer can. The draft never decides to file.

SM-RP-01 re-reads stored drafts. Zero drafts is `no_sample`. A tampered narrative fails the control. No external language model was called.

## Auditor bundle

`GET /compliance/evidence-export` returns a zip of the latest evidence payload per control plus `MANIFEST.json`. Compliance roles, including the auditor, can download it. The compliance page has that button. SM-AU-01 fails when a stored sha256 does not match the payload. Zero rows is `no_sample`. The zip is not committed.
