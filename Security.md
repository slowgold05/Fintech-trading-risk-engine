# Sentinel Markets security controls

This is a mock brokerage. The [threat model](docs/THREAT_MODEL.md), [control matrix](grc/control_matrix.csv), and [control workpapers](grc/workpapers) describe the implemented safeguards and their evidence. The [action items](docs/GRC_ACTION_ITEMS.md) track gaps that remain open.

## Authentication and access

Passwords are hashed with bcrypt through Passlib. Login has per-IP rate limits and per-account backoff. Access tokens use PyJWT with a configured secret and required expiry; refresh tokens rotate and their hashes are stored in PostgreSQL. The AWS demo serves HTTPS with secure refresh cookies, HSTS, and API docs disabled. The working tree can require a six-digit authenticator code before a session and before a large order. The secret is a `mfa-v1` keystream ciphertext derived from `JWT_SECRET`. Changing that secret makes every enrolled secret undecryptable, and recovery is re-enrollment rather than a backup code. Settle that rotation path before requiring MFA broadly. `MFA_REQUIRED` defaults to false, enrollment is incomplete, and the hosted image does not include this path, so the public demo still signs in with a password. Full access-token revocation is still open. Passkey signing is not implemented.

Trader routes require the trader role. Compliance routes require an admin, compliance officer, or auditor role, with mutation rights checked again by each endpoint. Admins request role changes, separate compliance officers approve them, and a privileged command applies them. The application database login cannot update `users.role`; a trigger records direct privileged role updates. SM-AC-01 and SM-AC-02 passed against the migrated AWS database.

## Trading and data integrity

Orders and direct trades require idempotency keys. Pre-trade checks enforce buying power, available shares, a 20% reference-price band, a 50% per-symbol concentration cap, and a $50,000 stock-position limit. Admins can halt or resume trading in the compliance console with an audited reason; a restart-based setting remains an emergency override. The latest hosted trading-halt, price-band, and idempotency operating checks had no live samples. Surveillance rules exist as versioned YAML in the working tree. A rule stays inactive until a different reviewer approves it, and that path is not on the hosted image. The model-risk policy is still a draft.

Paper withdrawals in the working tree require a legal name and a clear sanctions screen. With `YENTE_URL` empty, that screen uses a local fixture, not an OFAC or OpenSanctions list. A configured yente call fails closed. AML and incident rows follow the same second-person rules as surveillance. A SAR draft cites only the case event ids and cannot state a filing decision. The public demo does not run these checks. The 2026-11-04 tabletop ran in-process against sqlite. It did not target the public site.

Trade accounting uses `Decimal` and balanced, hash-chained ledger postings. The application database role cannot update or delete ledger rows, and PostgreSQL triggers reject those operations. SM-LD-01 reconciles ledger hashes, cash, and positions; a manual AWS run checked eight accounts with no failures. Local nightly reconciliation is scheduled; a hosted scheduler and independent evidence storage remain open.

## Verification limits

CI defines Gitleaks, Bandit, pip-audit, Semgrep, and Trivy gates alongside tests. The draft PR's 2026-10-31 migration-documentation run passed all six jobs. Four hosted application controls passed in an operator run; three reported `no_sample`. That evidence is saved on the development machine. New runs can also insert append-only `control_evidence` rows, which the console prefers. The live image does not include that table yet, so the console still shows `not_run` until the deployment in the AWS runbook. The privileged migration login can change triggers and grants. Lightsail deployment environment values are readable by project administrators. This public demo still lacks authenticator enrollment, a running hosted refresh schedule, and an evidence copy outside the database. The Q4 2026 access review was recorded on the live API. The working-tree authenticator is not on that image. These limits are tracked in the [action items](docs/GRC_ACTION_ITEMS.md) and [AWS runbook](docs/aws_deployment.md). How to report an issue, and how secrets are kept out of git, is in [docs/SECURITY.md](docs/SECURITY.md). The 2026-11-04 finding list is [AUDIT-001](docs/security/AUDIT-001.md). The expansion code, including propose-only intents and the risk brief, is in this working tree and is not on the hosted image. Approval of the policies and models remains pending.
