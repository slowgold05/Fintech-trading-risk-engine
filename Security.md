# Sentinel Markets security controls

This is a mock brokerage. The [threat model](docs/THREAT_MODEL.md), [control matrix](grc/control_matrix.csv), and [control workpapers](grc/workpapers) describe the implemented safeguards and their evidence. The [action items](docs/GRC_ACTION_ITEMS.md) track gaps that remain open.

## Authentication and access

Passwords are hashed with bcrypt (cost 12) by calling the `bcrypt` library directly. Login has per-IP rate limits and per-account backoff. Access tokens use PyJWT with a configured secret and required expiry; refresh tokens rotate and their hashes are stored in PostgreSQL. The AWS demo serves HTTPS with secure refresh cookies, HSTS, and API docs disabled. The hosted release supports a six-digit authenticator code before a session and before a large order or withdrawal. The secret is a `mfa-v1` keystream ciphertext derived from `JWT_SECRET`. Changing that secret makes every enrolled secret undecryptable, and recovery is re-enrollment rather than a backup code. Settle that rotation path before requiring MFA broadly. `MFA_REQUIRED` remains false and enrollment is incomplete. Enrolled users still need their code; a high-risk login without an enrolled factor is denied. Full access-token revocation is still open. Passkey signing is not implemented.

Trader routes require the trader role. Compliance routes require an admin, compliance officer, or auditor role, with mutation rights checked again by each endpoint. Admins request role changes, separate compliance officers approve them, and a privileged command applies them. The application database login cannot update `users.role`; a trigger records direct privileged role updates. SM-AC-01 and SM-AC-02 passed against the migrated AWS database.

## Trading and data integrity

Orders and direct trades require idempotency keys. Pre-trade checks enforce buying power, available shares, a 20% reference-price band, a 50% per-symbol concentration cap, and a $50,000 stock-position limit. Admins can halt or resume trading in the compliance console with an audited reason; a restart-based setting remains an emergency override. The hosted release supports versioned surveillance rules, case review, and independent activation approval. No rule was activated during rollout, and the model-risk policy remains a draft. Detector scans lock their cursor before reading events and cases, and complete event identities prevent reviewed activity from reopening unchanged.

Hosted paper withdrawals require a legal name, a clear sanctions screen, and available cash after reservations. With `YENTE_URL` empty, that screen uses a local fixture, not an OFAC or OpenSanctions list. A configured yente call fails closed. Cash balance, ledger postings, movement, and idempotency records commit together under a user-row lock. A stored successful withdrawal replays without a new screening decision. AML rules remain inactive until independently approved. An incident opener cannot record notice or close that case. A SAR draft cites only the case event ids and cannot state a filing decision. The 2026-11-04 tabletop ran in-process against sqlite; it did not target the public site.

Trade accounting uses `Decimal` and balanced, hash-chained ledger postings. The application database role cannot update or delete ledger rows, and PostgreSQL triggers reject those operations. SM-LD-01 reconciles ledger hashes, cash, and positions. The 2026-11-04 rollout reconciled all 14 accounts after smoke testing with no failures. The hosted scheduler runs with a database lease and persisted next-due time. Independent evidence retention remains open.

## Verification limits

All six CI gates passed for the application release in PR #12. The full local backend run passed 134 tests, including disposable PostgreSQL race and restricted-role proofs. The first hosted scheduled cycle stored evidence for 23 controls: 10 pass, 12 `no_sample`, and one MFA-enrollment failure. Five controls outside that cycle remained `not_run`. Evidence-export hashes verified. Live HTTP smoke tests passed, but browser click-through remains unverified because the automation service was unavailable.

The privileged migration login can change triggers and grants. It was used only through a temporary private runner and was not included in the web deployment; that runner was deleted after verification. Normal application credentials remain Lightsail environment values readable by project administrators. A secret manager, independent evidence retention, broad MFA enrollment and recovery, and policy/model-owner approval remain open. The Q4 2026 access review was recorded on the live API; the new smoke account still needs a review decision. These limits are tracked in the [action items](docs/GRC_ACTION_ITEMS.md), [AWS runbook](docs/aws_deployment.md), and [AUDIT-001](docs/security/AUDIT-001.md). Reporting instructions are in [docs/SECURITY.md](docs/SECURITY.md). The deployed expansion components remain demonstrations with the integration limits documented in the roadmap.
